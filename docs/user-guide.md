# 用户指南

## 安装

Desktop 和 Web 是独立 profile，两端都用时分别安装。下面的命令安装 npm 当前发布的版本；本文描述的是 1.0.x 的功能。

```sh
dsh plugin --profile desktop add dsh-builtin-browser
dsh plugin --profile web add dsh-builtin-browser
```

### 先移除再安装

DSH 会拒绝重复安装（`already-installed`），不会自动更新。已有版本时，保存进行中的工作，在需要更新的 profile 先运行 `remove`，再添加目标版本。下面以桌面端为例；把 `VERSION` 改成已发布的目标版本，更新 Web 时把 `desktop` 改成 `web`。

```sh
dsh plugin --profile desktop remove dsh-builtin-browser
dsh plugin --profile desktop add dsh-builtin-browser@VERSION
```

重启对应的 DSH 实例。不要为了更新而删除整个 `DSH_HOME`；里面有该实例的配置和站点会话数据。桌面端的宿主补丁与 profile 中的插件是两回事；更新 Desktop 后，另外检查 **设置 → 浏览器** 的桥接和补丁状态。

## 桌面侧栏（Windows / macOS）

1. 在 **设置 → 浏览器** 选择 **DSH 侧栏**，打开对话的浏览器侧栏。
2. 让 Agent 打开一个地址。宿主提供可驱动的侧栏时，Agent 和你操作的是同一页；打开链接时不会有独立 Electron 窗口。
3. 如桥接过旧或未就绪，保存工作后使用设置页提供的 **卸载并重装**。在 macOS 上，维护流程使用系统的退出请求；Windows 也走正常退出。若 DSH 提示有进行中的任务，可取消退出，维护不会强行结束会话。
4. 启动后查看桥接与宿主补丁结果。重复失败时保留诊断结果，先核对 DSH 版本与构建，不要手动覆盖 `app.asar` 或从旧版本复制备份。

### 宿主补丁做什么

受支持的 Desktop 构建可通过插件附带的补丁启用原生侧栏视图、真正的带 opener 子标签、后台会话渲染和 Desktop 主扩展。补丁只更改本机 DSH 文件，不需要改动上游仓库。应用前校验目标与备份；不匹配则拒绝应用。公开的版本号不是兼容性保证；参见[兼容性与边界](limitations.md#宿主与安装)。

如果部署不允许修改宿主，不要运行补丁流程。使用宿主原本就支持的侧栏能力；缺少能力时工具会说明原因，仍可手动浏览，或在允许的环境显式选择 Chrome / Edge。

## Web 侧栏

在 `dsh web` 的对话里打开侧栏浏览器。可以手动访问支持的网页、点击链接、填写支持的表单、发送选区引用。站点页在隔离的 iframe 中运行，不能读取 DSH 会话凭据或应用存储。

Web 侧栏并不是远程 Desktop：仅提供不依赖 opener 的子标签，不提供原生 CDP。网页功能如果依赖弹窗句柄、跨窗口消息或沙箱没有开放的 API，DSH 不会代替你在外部打开它。若任务需要原生控制，改用受支持的桌面侧栏，或显式选择运行 DSH 那台机器上的 Chrome / Edge。

## Chrome / Edge：独立配置或自己的浏览器

在设置里显式选择 Chrome 或 Edge。默认使用 DSH 管理的独立配置，与日常浏览器的登录态分开。

如果想使用已经登录的浏览器，选择偏好个人配置，按需点击 **一键安装扩展**。若扩展尚未加载，按浏览器提示启用开发者模式、选择 **加载解压缩的扩展程序**，并选中设置打开的文件夹；已连接时不需要重复操作。不需要复制配对令牌或运行终端命令。组织策略阻止加载扩展时，可以继续使用独立配置。

每个新会话只在开始时选择载体：扩展不可用时使用独立配置的 CDP，不直接调试个人配置；扩展晚些时候连上，也不会切走已运行的 CDP 会话。清理会话不会关闭你的个人浏览器窗口或原有标签。

## 划选和引用网页

1. 在侧栏选择文字、表格或含公式内容，在浮条里选择加入对话。
2. 发送前核对引用胶囊和评论。引用保存发送时的内容，而不是稍后重新去网页取正文。
3. 发送后悬停预览，或点 **回到原页面**。原标签不存在时会尝试在当前会话打开来源；页面已变化或选区无法重新定位时，仍可查看已保存的内容。

## 常用设置

| 设置 | 用途 |
| --- | --- |
| 安静模式 | Agent 操作不移动系统鼠标，不抬起前台窗口。浏览器自身的提示不受插件控制。 |
| 允许远程观看 | 提供只读画面，不把 Agent 的控制权交给观看者。 |
| Agent 权限 | 按部署需要决定是否允许脚本、下载和登录状态读写。 |
| 本机浏览器窗口模式 | 仅控制使用 DSH 独立配置启动的 Chrome / Edge；不是侧栏的无头开关。 |
| 下载交付 | 把已保存的文件交给 DSH 中配置好的上传工具，遵循原任务权限。 |

`browser.channel` 默认是 `sidebar`；旧的 `bundled`、`auto` 同样表示仅侧栏。外部浏览器用 `chrome` 或 `edge` 显式选择。不同会话的标签独立；侧栏站点登录状态可在同一个 `DSH_HOME` 内共享，Desktop 和 Web 各自保存，不互相复制。

## 给 Agent 的示例

> 打开 https://example.com，总结页面的主要内容，并保留来源。

常用浏览器工具默认可用。需要更多动作时按组加载；固定步骤用 `dsh_browser_do`，带循环或条件的程序用 `dsh_browser_code`（标准模式）或 DSH 的 `run_code`（PTC 模式）。提交类动作之后，应检查页面反馈或服务器响应，不能把“已点击”当作“已提交”。登录、验证码和敏感确认由用户接管。

## 故障排查

| 现象 | 怎么处理 |
| --- | --- |
| 桥接版本过旧或桌面升级后断开 | 检查设置中的桥接与补丁状态；保存任务后在兼容宿主上重装。 |
| 页面可手动打开，Agent 却报告原生载体不可用 | 手动 Web 侧栏不是 CDP 工具载体。改用支持原生控制的 Desktop，或显式选 Chrome / Edge。 |
| 切换对话后提示面板未展示 | 在不具备后台渲染支持的宿主上，先显示发起操作的会话。 |
| 本机浏览器打开后没有原来的登录态 | 检查当前是扩展 / 个人配置还是 CDP / 独立配置；扩展后连上时只影响下一次新会话。 |
| 网站不能登录或打开某种子标签 | Web 的沙箱能力有限，改用受支持的 Desktop 或本机浏览器；验证码交给用户。 |
