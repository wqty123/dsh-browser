# Attach to the running Edge / Chrome profile

Default `systemProfile: plugin` remains a separate DSH-owned browser/profile. The extension is **only** for explicitly selected `systemProfile: user`. It does not copy credentials, open a debugging port, launch your personal browser, or embed a native tab inside the DSH sidebar.

## One-time installation (unpacked pilot)

1. Extract the plugin package to a permanent directory. Keep Node 22+ installed at the same path used below. No plugin `node_modules`, npm install, administrator rights or build step is needed after extraction. The Windows helper is compiled locally using Windows PowerShell's built-in `Add-Type`/.NET Framework; enterprise execution controls may prevent this and must not be bypassed.
2. In the **intended signed-in profile**, open `edge://extensions` or `chrome://extensions`, enable Developer mode, choose **Load unpacked**, and select the extracted `browser-extension` directory. Copy the displayed 32-letter extension ID. This is a real one-time browser permission grant, not silent installation.
3. In a terminal run the extracted script, substituting **absolute paths** and the actual extension ID. Use the exact native-host directory printed by DSH settings (custom `DSH_HOME` installations must use their own directory):

   ```powershell
   node "C:\permanent\dsh-builtin-browser\native-host\install.mjs" --browser edge --extension-id aaaaaaaaaaaaaaaaaaaaaaaaaaaaaaaa --directory "C:\Users\you\.dsh\dsh-builtin-browser-host\extension\edge" --label "My Edge profile"
   ```

   For Chrome use `--browser chrome` and an independent `...\extension\chrome` directory. On macOS/Linux use normal absolute POSIX paths. Registration is per-user: HKCU `Software\Microsoft\Edge\NativeMessagingHosts\com.dsh.browser.edge` or `Software\Google\Chrome\NativeMessagingHosts\com.dsh.browser.chrome`; macOS `~/Library/Application Support/{Microsoft Edge,Google/Chrome}/NativeMessagingHosts`; Linux `${XDG_CONFIG_HOME:-~/.config}/{microsoft-edge,google-chrome}/NativeMessagingHosts`. Stable desktop installations only; sandboxed/distribution-specific browsers may not support these locations. Failure is explicit, never a profile fallback. `--no-register` produces assets without touching browser registration.
4. Open the extension's **Options** in that same profile. Click **Connect / resume** if needed, paste the terminal's one-time token, and click **Pair this profile** within five minutes. Tokens are stored only as SHA-256 digests, consumed once, and never persisted in extension storage. A random profile installation ID binds reconnects to that profile. Pairing another profile requires explicitly running the installer again, which rotates credentials and revokes the prior connection.
5. Select the corresponding browser and **Attach to current browser** in DSH settings. Status must say connected and name your controlled profile before use. Open a normal browser window yourself first: the extension never creates windows. Agent tabs are inactive and remain in this browser/profile, with its actual logins. Personal/adopted tabs are detach-only. Explicit close can remove only agent-created tabs belonging to the requesting session.

Keep the extracted package in place; the registered launcher refers to it and the absolute Node executable. Re-run installation after moving either. Store distribution/signing is not implemented by the unpacked pilot; ordinary store installation also cannot hide the debugger warning. No policies or browser launch flags are altered.

## Security and revocation

The browser checks an exact extension-ID `allowed_origins` list; the native host separately checks its browser-supplied origin. Extension options accept messages only from their own exact extension options URL. There is no website bridge, externally-connectable API, localhost web listener, cookie permission or host permission. The plugin connects over a local named pipe / private Unix socket and authenticates with HMAC-SHA256 over a fresh per-connection challenge, relay epoch and paired profile ID. Frames are bounded to 256 KiB, responses to 8 MiB (ordered chunks), outstanding operations to 32, and operations expire without automatic replay. Configuration is private (0700/0600 on Unix; current-user ACL on Windows). No protection against malware running as the **same OS user** is claimed.

Extension Options **Disconnect** or the debugger infobar's **Cancel** releases attachments and pauses automatic reconnect. Resume explicitly from Options. To revoke permanently, re-run the install command with `--revoke`; it removes pairing, rotates the IPC secret and disconnects a running relay. Remove the extension and HKCU native-host key (or the per-user manifest) to uninstall. Revocation/disconnect never closes tabs/windows, clears cookies, or shuts down a browser.

## Quiet-mode policy and unavoidable browser UI

DSH never sends OS input, activates/highlights tabs, focuses windows, opens a popup, or displays a takeover banner in this browser. It creates only `active:false` tabs in an existing normal window. Input uses CDP `Input.dispatch*`; text insertion is translated to `Input.dispatchKeyEvent`. Virtual focus emulation and page lifecycle activation affect the renderer only. Page screenshots use `Page.captureScreenshot` in the background, never visible-tab/screen capture; dimensions are capped at 1280×960, aggregate transport payloads at 8 MiB, with attachment bounds enforced again by DSH.

Site-created tabs are detected through tab/window creation events, tied to an agent-tab opener. Popup-window tabs are moved into the opener's existing normal window without activation/focus calls. Already-background normal tabs stay background. An already-active normal tab cannot reliably be deactivated without activating another tab, which this extension deliberately never does. Browser events arrive after creation, so a site's own initial activation/focus can precede containment; this is reported, not undone with focus-stealing calls. Unrelated personal-tab popups are untouched. Related site-created tabs do not acquire agent-close authority merely because they have an opener.

Agent-created tabs receive page-scoped guards for common notification, geolocation, media/display capture, clipboard, Bluetooth/USB/HID/serial and file-picker permission requests. These deny the JavaScript request before a prompt, in current/new documents, without changing browser-wide permissions. They are best-effort page code, not a browser security policy: hostile pages, other APIs and already-open frames can bypass them. Adopted personal tabs do not receive these guards. No browser-context permission/download setting is changed.

File choosers are intercepted, and JS alert/confirm/prompt/beforeunload dialogs dismissed through `Page.javascriptDialogOpening` / `Page.handleJavaScriptDialog`. A notice is delivered as an explicit error on the next page operation (and as a page event); no success is fabricated. Quiet-interception setup failure rejects the control lease. Cookie import/export, downloads, arbitrary file upload, browser-wide CDP, target creation/activation/close commands are unavailable. Do not set `Page.setDownloadBehavior`: despite its Page-domain name it changes download behavior for the shared browser context, including personal tabs. These v1 permissions do not offer reliable per-tab blocking of website-initiated downloads.

**This is not a guarantee that arbitrary websites or browser-owned UI can never appear.** Normal `chrome.debugger` installs show a browser-wide “being debugged” infobar; there is no normal API to hide it. Website-initiated downloads, OS/browser permissions, enterprise/security UI, external-protocol handlers, and site-created tabs/windows are not comprehensively suppressible using these v1 permissions. `Runtime.evaluate` executes page code; it is not a sandbox against a page's own popup/focus attempts. Do not use attach mode if absolute invisibility or zero browser-owned UI is required. DSH does not fake policy installation or weaken browser security. A stricter browser-wide popup/permission policy needs a separate user-approved deployment decision.

## Laptop acceptance (Edge and Chrome separately)

1. Keep personal browser windows, tabs and another browser instance open. Record their PIDs, tab URLs and window handles. Install/pair only the selected profile; attempts from another extension ID/profile, used token or expired token must fail.
2. In a Windows PowerShell session record `GetForegroundWindow()` and `GetCursorPos()` from `user32.dll` via `Add-Type`, immediately before and after the agent run. Require **identical foreground HWND and cursor coordinates**, and no unexpected new window. Keep hands off mouse/keyboard during measurement. Do not dismiss the debugger infobar during the run; record its actual wording/appearance separately.
3. Have the agent open an inactive tab, navigate to a local fixture and signed-in GitHub, snapshot/a11y, click/type using CDP, and capture an image. Keep another tab active throughout. Require the image to show the hidden page's expected text/pixels, not the foreground tab; record image dimensions. Repeat with the browser minimized. This is real-Edge acceptance, not established by fake-API tests.
4. Trigger alert/confirm/prompt/beforeunload and a file chooser: no native dialog should open on attached tabs; the model must see the disposition. Record website download/permission/external-protocol/site-popup limitations rather than claiming those are suppressed. Verify personal-tab download settings have not changed.
5. Request human takeover: the DSH chat card is the only DSH prompt; no Edge banner, focus or tab activation. Complete/skip and require fresh summaries from the same tab.
6. Cancel the debugger infobar, disconnect Options, restart DSH, revoke/re-pair, and close the controlled tab. Each old lease must fail without replay or automatic reattachment against revocation. Detach/session cleanup leaves all tabs open; explicit close removes only the agent's tab. Run managed-mode cleanup while personal Edge is open and verify every personal process/window survives.

Current automated tests cover a fake debugger and the real native IPC/framing/authentication/pack-extract path. They do **not** establish Windows registration, actual Edge warning UI, hidden-tab pixels or foreground/cursor invariance; run the laptop steps before claiming those.

### Windows inline commands (no new script files)

Run Edge first; repeat separately with Chrome. The browser UI actions below are deliberate human installation/acceptance actions, not DSH focus calls. Substitute the package path and extension ID. Never paste the pairing token into chat or commit it.

1. In PowerShell initialize paths: `$pkg=(Resolve-Path 'C:\permanent\dsh-builtin-browser').Path; $browser='edge'; $node=(Get-Command node).Source; $root=if($env:DSH_HOME){$env:DSH_HOME}else{Join-Path $HOME '.dsh'}; $dir=Join-Path $root "dsh-builtin-browser-host\extension\$browser"; $ext=Read-Host '32-letter extension ID'`. Before entering the ID, load `$pkg\browser-extension` from `edge://extensions` in the intended signed-in profile (for Chrome, set `$browser='chrome'` and use `chrome://extensions`).
2. Install/register/pair: `& $node (Join-Path $pkg 'native-host\install.mjs') --browser $browser --extension-id $ext --directory $dir --label "My $browser profile"`. In extension Options click **Connect / resume**, paste only this terminal's token, then **Pair this profile** within five minutes. Keep the package and Node paths unchanged.
3. In the DSH window's DevTools console select attach mode: `await fetch('/dsh-builtin-browser/settings',{method:'PUT',headers:{'Content-Type':'application/json'},body:JSON.stringify({browser:{channel:'edge',systemProfile:'user'}})}).then(r=>r.json())`. For Chrome replace `edge` with `chrome`. Check `await fetch('/dsh-builtin-browser/runtime-status').then(r=>r.json())`; require `resolvedCarrier: 'extension'`, `controlledProfile: 'user'`, `readiness: 'ready'`, and the expected profile/connection ID. Before pairing or with Options disconnected require blocked, never another carrier.
4. In a second PowerShell terminal start the memory-only fixture (leave running; Ctrl+C afterwards): `& $node -e 'require(`node:http`).createServer((q,s)=>{s.setHeader(`Content-Type`,`text/html`);s.end(`<title>DSH hidden fixture</title><body style=background:rgb(221,17,153)><p>before selected words after</p><input aria-label=Name><button onclick=this.textContent=42>Continue</button><button onclick=alert(1)>Alert</button><button onclick=confirm(1)>Confirm</button><button onclick=prompt(1)>Prompt</button><input type=file><a href=/popup target=_blank>Popup</a></body>`)}).listen(8765,`127.0.0.1`)'`. In that terminal first set `$node=(Get-Command node).Source` if needed. Ask the agent to use `http://127.0.0.1:8765/` and signed-in GitHub; verify snapshot/a11y, click/type, hidden-page screenshot pixels/dimensions, selection quote/reveal and same-tab takeover completion/skip. Trigger dialogs/file chooser and record dispositions. Site-popup/download/permission exceptions remain as above. Repeat minimized.
5. In the first terminal record browser identities: `$processName=if($browser -eq 'edge'){'msedge'}else{'chrome'}; $personal=Get-Process $processName | Select-Object Id,StartTime,MainWindowHandle; $personal | Format-Table`. Record personal tab URLs/windows manually too. For a hands-off foreground/cursor interval run `$probe=Start-Job { Add-Type 'using System; using System.Runtime.InteropServices; public static class DSHQuietProbe { [StructLayout(LayoutKind.Sequential)] public struct Point { public int X,Y; } [DllImport("user32.dll")] public static extern IntPtr GetForegroundWindow(); [DllImport("user32.dll")] public static extern bool GetCursorPos(out Point p); public static string Read() { Point p; if(!GetCursorPos(out p)) throw new Exception(); return GetForegroundWindow().ToInt64()+"|"+p.X+"|"+p.Y; } }'; Start-Sleep 15; $before=[DSHQuietProbe]::Read(); $at=Get-Date; $changes=0; 1..480 | ForEach-Object { Start-Sleep -Milliseconds 250; if([DSHQuietProbe]::Read() -ne $before){$changes++} }; [pscustomobject]@{Started=$at;Ended=Get-Date;Before=$before;After=[DSHQuietProbe]::Read();ChangedSamples=$changes} }`. Return to DSH within 15 seconds and keep hands off during the two-minute interval. Arrange for the agent's browser operations to start **after** the baseline and finish before the interval ends; a run outside that interval is inconclusive. Afterwards run `Receive-Job $probe -Wait -AutoRemoveJob`; require identical Before/After, `ChangedSamples=0`, and manually verify no unexpected window. Do not focus PowerShell to retrieve results until the interval is over. Repeat minimized; do not dismiss the debugger infobar during measurement.
6. After measurement, exercise Options Disconnect, infobar Cancel, DSH restart, controlled-tab closure, and replay of old handles: old operations must fail, not reattach/replay. Revoke with `& $node (Join-Path $pkg 'native-host\install.mjs') --browser $browser --extension-id $ext --directory $dir --revoke`; readiness must become blocked. Re-run step 2 and pair the new token; used/expired tokens and wrong IDs/profiles must be rejected. Detach/session cleanup leaves all tabs open; explicit close removes only an agent-created tab.
7. Test managed cleanup separately, outside the quiet measurement. In DSH console run `await fetch('/dsh-builtin-browser/settings',{method:'PUT',headers:{'Content-Type':'application/json'},body:JSON.stringify({browser:{channel:'edge',systemProfile:'plugin'},cookies:{persist:true}})}).then(r=>r.json())`. Ask the agent to open a **builtin** page; runtime status must name the plugin profile and become ready only with live CDP. Switch back using step 3 to clean up the managed carrier. In PowerShell run `$missing=@($personal | Where-Object { $p=Get-Process -Id $_.Id -ErrorAction SilentlyContinue; !$p -or $p.StartTime -ne $_.StartTime }); $missing | Format-Table; "MissingOriginalProcesses=$($missing.Count)"`; require zero missing original personal processes and manually verify every original personal window/tab remains. Natural browser process turnover can make this check inconclusive: investigate rather than treating it as a pass. Use `chrome` in the console bodies for the Chrome run.

The fixture and measurement commands run from memory; no additional `.ps1`/`.js` files are required. Native-host installation still creates its documented registration/launcher assets. These commands do not prove Windows acceptance until run and the stated observations recorded.

Linux Chromium 156 probe: real `chrome.debugger` attached an inactive agent tab, navigated to a magenta fixture and captured PNG pixels through `Page.captureScreenshot`. The active tab ID was unchanged; the agent tab remained `active:false`; output was 780×380 with the expected RGB (221,17,153). Focus emulation made the page report `document.visibilityState === 'visible'` even though its browser tab was inactive. Evidence: `BT-hidden-tab.png` and `BT-hidden-tab-probe.log`. This does not establish minimized-window behavior, Windows foreground/cursor invariance or Edge behavior.
