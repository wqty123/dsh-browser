# v1.1.0 任务单：硬编码清零 + 兼容性架构与 DSH `v0.2.3-alpha.2` 适配

基于当前 `master`（已完成 `#74` `tool-browser` 与 `#76` `provider` 拆分），请按顺序拆分为 **2 个独立 PR** 完成以下改造。每个 PR 均需通过全量测试、`tsc --noEmit`、`pnpm build` 及 `npm pack --dry-run`。

---

## 硬性红线（两个 PR 均须遵守）

1. **禁止硬编码个人路径、盘符或端口**：严禁保留类似 `D:/dsh-home/...`、`C:\Users\...` 或写死的 `3080` / `9222` 端口兜底。
2. **禁止用 DSH 版本号字符串做 `>=` 分支判断**：官方为 `0.2.3-alpha.2`，社区壳为 `0.14.0`，版本号不可比；一律改用运行时特性探测。
3. **禁止对第三方桌面壳（如 `dataelement/dsh-desktop`）写 `app.asar` 字节补丁**：第三方壳只做识别与友好降级引导，绝不强改其宿主文件。
4. **保持抽象轻量**：能力契约与特性探测模块总代码量保持精简直观，不要过度套工厂或重型多层适配器。

---

## PR 1：硬编码清零 + 静态守卫 + 载体能力契约

### 1. 清零 `docs/hardcoding-audit.md` 遗留硬编码

- **`src/tool-browser/state.ts`**：删除 `readSurface()` 中硬编码的 `'D:/dsh-home/dsh-builtin-browser-host/settings.json'`，统一只通过 `settingsPath()` / `SettingsStore` 读取（并视情况接入 Cordis 配置同步）。
- **`src/tool-browser/*`**：
  - 将内联的默认超时、wait 预留/下限、`MAX_FILL_FIELDS` 以及 settings / open-request / reference 路由路径统一收口到 `assets/browser-policy.mjs` 导入，避免多处重复定义。
  - 检查工具描述中的固定示例端口（`127.0.0.1:3080`），改为泛化占位表述（如 `127.0.0.1:<port>`）并与 `DSH_WEB_URL` 守卫逻辑对齐。
- **根目录 `client.js` 核查**：确认该文件是否为历史遗留产物；若不再被打包或外部引用则移除，避免残留旧版 `[class*=_tabStrip]` 代码。
- 同步更新 `docs/hardcoding-audit.md`，标记上述项已清零。

### 2. 引入轻量载体能力契约：`src/browser/capabilities.ts`

- 定义 `CarrierCapabilities`：
  ```ts
  export interface CarrierCapabilities {
    readonly cdp: boolean
    readonly liveSnapshot: boolean
    readonly interaction: boolean
    readonly screenshot: boolean
    readonly nativeTabs: boolean
    readonly backgroundRender: boolean
    readonly takeover: boolean
    readonly referenceCapture: boolean
  }
  ```
- 提供统一门禁 `assertCapability(capabilities, required, context)`，替代散落在 `tool-browser/*` 各处的 `panelUrlByTask` 零散判断与重复报错文案。
- 缺失能力时抛出带结构化错误码（对齐 DSH `0.2.3-alpha.2` 工具错误规范）与可执行切换建议的错误。

### 3. 新增源码静态守卫测试：`tests/no-hardcoding-guard.test.mjs`

- 扫描 `src/` 与 `desktop-bridge/`（排除测试夹具与显式白名单注释）：
  - 拦截个人盘符绝对路径（如 `[A-Za-z]:/dsh-home`、`[A-Za-z]:\\Users\\`）；
  - 拦截 CSS Modules 类名子串硬编码（如 `_tabStrip`、`_tabHost`、`acoR2W_`）；
  - 拦截对 `dshVersion` / 宿主版本号做字符串比较的分支。

## PR 2：桌面壳结构化识别 + DSH `v0.2.3-alpha.2` 适配

### 1. 宿主与外壳结构化识别（解决 #62 困惑，但不硬 patch 第三方壳）

- 改造 `desktop-bridge/desktop-identity.json`、`desktop-bridge/install.mjs` 与 `src/browser-electron/bridge-status.ts`（可收口至 `src/browser-electron/host-identity.ts`），输出结构化 `DesktopShellReport`：
  - `kind`: `'official-supported' | 'official-unsupported' | 'third-party-shell' | 'none'`
  - `patchable: boolean`、`reason: string`、`recommendedCarrier: 'sidebar' | 'chrome' | 'edge'`
- **明确区分第三方壳**：当探测到 `name: "dsh-desktop"` 且入口为 `out/main/index.js`（如 `dataelement/dsh-desktop` 0.13.2+ / 0.14.0）时，判定为 `third-party-shell` 且 `patchable: false`，**禁止报 `missing lib/main.js`**；在设置页隐藏“安装/修复桥接”按钮，明确提示“检测到第三方 DSH Desktop 壳，不支持宿主补丁，请切换至本机 Chrome / Edge 载体”。
- 保留并验证多级路径探测顺序：`DSH_DESKTOP_PATH` / `DSH_DESKTOP_APP` → 运行中进程路径 → Windows 卸载注册表 → 平台约定目录。

### 2. 彻底移除 CSS Modules 类名依赖

- 清理 `src/client/settings/panel.ts`、`desktop-bridge/plugin-browser-bridge.js` 及对应测试中对 `[class*=_tabStrip]`、`[class*=_tabHost]` 的依赖。
- 全面改用稳定的 `data-*` 属性（如 `[data-sidebar-right-session]`）和官方注入的 UI 服务 / 宿主协议，确保在 `v0.2.3-alpha.2` 新 CSS Modules 类名格式下正常工作。

### 3. 运行时特性探测与 DSH `v0.2.3-alpha.2` 对齐

- 新增 `src/compat/host-features.ts`，集中探测运行时能力（不查版本号）：
  - `ctx.tools.register` 是否支持 `{ when }` 条件注册；
  - `ctx.get('ptcRuntime')` 存在性（验证 `v0.2.3-alpha.2` 新版 Node PTC `run_code` 下调用 `dsh_browser_*` 核心工具与截图附件的兼容性）；
  - Cordis `4.0.0-rc.12` 前后端配置同步能力与 `cordis.patch.yml` / `inject` 校验；
  - 渲染端 `window.dshDesktop?.protocolVersion >= 1` 窄桥探测。
- 核对 `@deepseek-ai/*` 导入路径（对齐 `0.2.3-alpha.2` 规范化导出：仅从包根或 `/types` 导入；按需核对 `dsh-client-ui-session-status` 与客户端样式挂载结构）。
- 核对 `dsh-host-patch` 在 `dsh-v0.2.3-alpha.2` 构建下的锚点匹配：如不匹配则标记为 `official-unsupported`（不强行改写），并在 PR 说明中列出需要补录的新锚点清单。
- 同步核对 `package.json` 的 Node 引擎说明（`alpha.2` 要求 Node `>=24.22.3` / `>=26.13.1`）与 CI 运行环境。
