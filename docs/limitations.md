# 兼容性与边界

## 宿主与安装

- **DSH 版本要求：** `1.0.x` 要求 DSH **`>=0.2.2-rc.3 <0.3.0`**（CI 持续验证 `0.2.2-rc.3`、`0.2.2-rc.5` 与 `0.2.3-alpha.2`）。仍内置 `0.2.2-rc.1` 的桌面端（如 `dataelement/dsh-desktop` 0.14.0）请待桌面端升级底座，或暂留在 `0.5.8`。
- **Desktop：** Windows 和 macOS 提供设置内桥接维护。可用功能取决于宿主公开的接口及桥接状态。宿主补丁按 DSH **0.2.2-rc.3 / rc.5** 的受支持构建校验，不承诺同版本号的任意产物都能应用；rc.5 Desktop 的补丁基线来自源码构建，不代表已验证所有分发包。遇到无法识别的文件、备份或冲突修改时会拒绝，而不是强行安装。
- **Web：** 有手动浏览和引用，没有 Desktop CDP、原生视图及 opener 语义。Web 宿主补丁不把 iframe 升级成原生浏览器。
- **无独立回退：** 默认和旧的 `bundled` / `auto` 值都只使用侧栏。不存在自动下载 Electron 或自动选择外部浏览器的路径。
- **原生子标签：** 有协议支持的 Desktop 将真正的浏览器子页放在同一侧栏。Web 和仅有 URL 通知的旧宿主只支持不依赖 opener 的子标签；不伪造窗口句柄，也不会用覆盖原标签冒充新标签。见[子标签契约](child-tabs.md)。
- **安静模式：** 插件的操作不抢系统焦点或移动系统鼠标。浏览器的调试提示条、权限提示、下载提示等不受插件控制。

## Web 隔离与站点兼容性

网页和嵌套 iframe 由代理承载，站点 Cookie 由插件保管，不读取 DSH 应用自己的凭据。**但在 DSH 0.2.3 上网页与 DSH 同源**：宿主的 Host 围栏拒绝一切带 `Origin: null` 的请求，而沙箱化的隔离来源（opaque origin）取图片、样式、脚本时正是发这个值——实测整页图片与样式全部 403，页面因此丢格式、丢图。给 guest 同源权限是当前唯一能让页面正常渲染的方式，所以**放进侧栏的网页要当作可信站点**：它和应用同源，能触达同源存储与接口。要恢复真正隔离，需要宿主侧对这条 guest 路由放行 `Origin: null`，插件才能退回隔离来源。

依赖跨窗口登录、worker 或其它受限能力的页面仍可能需要 Desktop 原生侧栏或本机浏览器。

嵌套文档仍受响应沙箱约束。由于同源祖先无法与 `frame-ancestors` 的语义区分，guest 路由不使用 `frame-ancestors` 来禁止所有外部嵌入；隔离边界不是防点击劫持保证。

## 登录态与接管

- Desktop 原生侧栏和 Web 代理各自在 `DSH_HOME` 下保存站点登录状态。归同一个 DSH 实例的侧栏共享站点登录，不按任务分开；Desktop 和 Web 不互相导入。已保存的会话 Cookie 不人为添加过期时间，主动退出和到期仍生效。不要共享或上传状态目录。
- 本机 Chrome / Edge 的独立配置不等于用户的个人配置。只有可用的个人浏览器扩展可以复用后者；回退的 CDP 会话没有个人浏览器的登录态。
- 持久会话不是 `dsh_browser_auth` 的导入／导出；该工具还受独立的读写权限和当前站点范围限制。URL 不明时拒绝导出，不扩大范围。
- CAPTCHA、滑块、登录和其它敏感确认由人工接管。插件不会绕过站点验证或重新提交敏感动作。
- 拦截识别基于页面特征，尽力而为：未识别不代表没有拦截。`dsh_browser_open` 只对拒绝访问类（403/429、「Access denied」）暂停后在新会话中重试一次；人工验证交给人工接管，IP/网络封锁（如数据中心 IP 被拒）是运行环境的限制，不重试也不绕过，改用结果里列出的备用公开来源（站点 API、搜索结果、存档）。新会话不清除浏览器配置中的 Cookie。

## 截图

截图和尺寸设置取决于所选载体。桌面侧栏请求 JPEG 时可能得到 PNG；读取返回的媒体类型。整页截图在部分软件合成环境下可能失败，必要时改用视口截图。只读远程预览不是 Web guest 的 CDP 截图接口。

## 权限与门控

- `dsh_browser_restrict` 是防误操作的**软护栏**,不是安全边界:模型可以自行解除白名单。要一个**模型拿工具改不掉**的限制,用设置页「Agent 能做什么」的三个动作开关(它们写在设置文档里,`dsh_browser_*` 工具没有一个会写它),或部署级的 `tool-browser` 配置 `allowedActions`(见 `cordis.patch.yml` 的注释)。
- **这条边界要说准**:设置走的是本机 HTTP 端点,写入要求带同源 `Origin`(裸 HTTP 客户端因此写不进去),但**同源页面仍然可以写** —— 这是"插件暴露了一个 HTTP 端点"的固有代价,它**不是凭据系统**,面板上的说明也是这么写的。
- 设置文档**存在但读不懂**(JSON 损坏、写到一半、权限读不到)时,四个**门控**开关(`credentials.allowRead` 与三个动作开关)一律按**关**处理,其余设置取默认值 ——"读不透操作者的意图"不等于"操作者什么都允许"。文件**不存在**(首次运行)仍按默认值。单个门控字段类型不对(`"false"` 字符串、`null`、数字)同样按**关**;门控所在的**小节**整个写成非对象(如 `actions: false`)也按**关**,而不是把里面的每个开关当成"缺席"、各取放行的默认值。

## 下载与保存路径

- `dsh_browser_download` 在页面上下文内 `fetch`(带登录态),受同源/CORS 约束;仅允许 HTTP(S) 目标。
- `savePath` 必须为**绝对路径**且位于 `downloadDir` 内(默认系统下载目录,自动识别 `Downloads`/`下载`/`下載` 与 `XDG_DOWNLOAD_DIR`,可用 `downloadDir` 覆盖),**不覆盖已存在文件**;`dsh_browser_screenshot` 的 `savePath` 走同一准入门。
- 单文件上限 **256MB**(流式限流,按 Content-Length 提前拒绝),文件由浏览器子进程直接落盘。下载与截图使用独占的随机临时文件,不会覆盖既有 `.part` 或最终文件;支持硬链接的文件系统原子提交,不支持时用独占复制提交,该回退在进程崩溃时可能留下未完成的新文件。
- 准入还会解析路径的**真实归属**:`downloadDir` 里的符号链接无法把写入带出目录,悬空链接同样被拒(它读作"名字已被占用",而不是"路径空闲")。

## 本机浏览器窗口模式

`browser.headless` 只用于 DSH 启动的独立 Chrome / Edge 配置。默认 `auto` 根据显示环境选择窗口或无头；`headless` 强制无头，`windowed` 要求显示可用。它不会改变 Desktop 或 Web 侧栏，也不控制扩展连接中的个人浏览器。
