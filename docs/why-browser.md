# 为什么做共享真实浏览器

网页任务经常需要人在关键时刻核对结果、接管登录或同意某个操作。只抓取页面无法完成这些交互；在后台另起浏览器虽然可交互，却让用户看不到真实操作。

插件优先使用 DSH 侧栏。在支持原生驱动的 Desktop 上，Agent 和用户操作同一个可见页面。切换对话不会把任务的浏览器借给另一个任务。引用保留来源和选区内容，用户可以看见 Agent 引用了哪段原文，而不只是一串链接。

这个设计有两条取舍：

- **同一侧栏比自动回退更重要。** 不支持的能力明确报错；Web 选择隔离浏览与引用，不能冒充原生 Desktop。需要外部浏览器时由用户显式选择。
- **任务归属与登录态分开。** 标签和操作记录按任务隔离，同一载体的站点会话可按 `DSH_HOME` 共享；需要独立登录时使用独立的 DSH 实例或独立浏览器配置。

人机验证交给人。另见[兼容性与边界](limitations.md)。
