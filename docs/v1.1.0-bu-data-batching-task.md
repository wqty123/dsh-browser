# v1.1.0 任务单：Browser Use 增强（隐藏数据源发现 + 真批处理与条件等待）

目标：放大 `dsh_browser_code` REPL 在数据发现和批量执行上的优势，减少“一步一个 cell”和盲目 `sleep()`，并与已完成的 `checkpoint()` 形成闭环。

> **命名约定**：下文出现的方法名与参数名仅作语义示意，**最终命名与签名请由实施者结合现有 `code-worker.ts` / `page-probe.ts` 的命名风格统一决定**，保持全仓一致即可。

---

## 一、隐藏数据源发现（Page Probe + REPL Helper）

### 1. 探针侧改造（`src/tool-browser/page-probe.ts`，同步递增 `PROBE_VERSION`）

- **轻量 JSON 响应采样**：在现有 `fetch` / `XHR` 钩子中，仅对 `2xx/3xx` 且 `content-type` 含 `json`（或 URL 含 `.json`）的响应做采样。
  - **硬保护**：严格跳过 `text/event-stream` 及声明超过 `2MB` 的响应；对无 `content-length` 或分块传输的响应，读取流时做硬字节截断（例如读取上限后立即 `reader.cancel()`）并加短超时保护，防止长连接或超大响应阻塞/撑爆内存。
  - **只存紧凑 schema 摘要**（不存全文），例如：`array(24) [{city, country, address, phone}]` 或 `object {total: 241, items: array(24)}`。
- **新增数据源扫描方法**（总输出控制在约 1–2KB 以内），一次返回 4 类线索：
  1. **内嵌状态脚本**：扫描 `#__NEXT_DATA__`、`#__NUXT_DATA__`、`window.__INITIAL_STATE__`、`window.__APOLLO_STATE__` 及 `<script type="application/json">` / `application/ld+json`，返回节点 id / 变量名、字节数、顶层 keys 及主要数组路径。
  2. **已拦截的 JSON API**：列出 `method`、`url`、`status` 及 schema 摘要。
  3. **Resource Timing 静态/首屏数据资源**：扫描 `performance.getEntriesByType('resource')`，筛出 `.json`、`/api/`、`graphql`、`locations`、`stores`、`search` 等高价值 URL（补齐探针注入前首屏已发完请求的盲区）。
  4. **页面声明端点**：扫描 `<link rel="preload" as="fetch">` 及常见 `data-api` / `data-endpoint` 属性。

### 2. REPL 侧暴露两个 Helper（`src/tool-browser/code-worker.ts`）

- **数据源巡检 Helper**（如 `inspect_data_sources()`）：调用上述探针方法并返回紧凑可读的列表/表格。
- **同源 JSON 拉取 Helper**（如 `fetch_json(url, init?)`）：在页面上下文带同源 Cookie 发 `fetch`，自动校验 `res.ok`、解析 JSON，非 2xx 时抛出带状态码和前 200 字符响应体的清晰错误。

## 二、真批处理与条件等待（替换盲目 `sleep()`）

### 1. 补齐确定性条件等待 Helper（`code-worker.ts`）

- **表达式轮询等待**（如 `wait_until(jsExpr, opts)`）：页面内轮询表达式直到 truthy，默认 ~200ms 间隔，超时返回最后一次求值结果便于排错。
- **文本出现 / 消失等待**（如 `wait_for_text` / `wait_for_gone`）：复用探针文本检测能力，暴露为 REPL 一等函数。
- **网络响应等待**（如 `wait_for_response`）：支持“先记 cursor → 执行触发动作 → 等匹配响应”的无竞态模式，复用现有 `networkCursor` 机制。
- **新标签页等待**（如 `wait_for_new_tab(triggerFn?, opts)`）：记录当前 tab 集合 → 执行触发动作 → 轮询并返回新出现的 tab handle。

### 2. 对固定 `sleep()` 做温和纠偏（不禁用）

- 保留 `sleep(ms)`，单次上限卡在 10s。
- 若同一任务中连续 2 次及以上调用 `sleep()`，在返回值中附带一句轻量提示，引导改用条件等待原语。

### 3. 动作后附带轻量状态回执

- 为 `click` / `type` / `fill` / `key` / `select` 返回值附加极简结构化变更摘要（如 `{ urlChanged, url, title, activeTag, newAlerts }`），让模型在同一个 cell 内就能判断动作是否生效并继续后续步骤，不必被迫结束 cell 再调 `snapshot()`。

## 三、提示词与使用范例更新（`CORE_PROMPT` / `SKILL.md`）

1. **数据源优先起手式**：明确引导——抓取多条列表、门店目录、多页数据或懒加载内容前，先调用数据源巡检 Helper，有现成 JSON/API 优先批量拉取，没有再翻 DOM。
2. **补充 2 个极短（<10 行）的真批处理范例**：
   - 范例 A（单页表单/筛选闭环）：单 cell 内串行 `fill → click → 条件等待 → js() 提取 → print()`。
   - 范例 B（多页/批量拉取闭环）：单 cell 内循环翻页或限流批量拉取 JSON → 分批调用 `checkpoint()` 落盘 → 打印汇总。
3. **写清批处理边界**：确定性高的步骤合并进一个 cell；首次进入陌生站点或可能遇到登录墙/弹窗的探索步骤保持短 cell，避免盲猜多步点击。
4. **交付前完整性自检**：引导在收尾 cell 中用 JS 统计并 `print()` 总条数、去重数、各必填字段缺失数与来源 URL，在交卷前暴露漏项并留下轨迹证据。
